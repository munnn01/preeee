# V7 H.265 `mc3_18` diagnostic on the previously used DEV sources

This protocol is locked before any V7 `mc3_18` inference. It is an **exploratory DEV diagnostic**, not a new holdout, not a fresh independent-analyzer test, and not a replacement for the original two-primary-analyzer gate (<−15% BD-rate Top-1 on both). `mc3_18` outcomes from earlier V2/V4/V6 studies have already been seen. The V7 selector was chosen using only CAL, then evaluated on DEV for the two primary analyzers; this diagnostic must not change the frozen V7 policy or models. A later confirmatory claim needs new source-disjoint videos and a separately locked protocol.

## Execution and analysis

Partition the ordered 200 DEV IDs by position modulo four; four private Kaggle jobs each process exactly 50 IDs, with no overlaps. Within each source and QP, encode/decode the distinct streams needed for identity, V6 and V7 exactly once and reuse that decoded result when names coincide. Reject a source if it is missing, duplicated, undecodable, has a different byte SHA, has an unmapped label, or produces a different selected candidate or codec bitrate than the locked V2 cache (absolute bpp tolerance `1e-9`). Do not substitute videos or drop failed rows. If any shard is incomplete, report **CHƯA ĐO** for the merged result.

Record the predicted class and correctness for all three arms at every QP, realized bpp, selection names, source SHA, codec/analyzer versions, git commit, selection-manifest hash and shard fingerprint. The worker may checkpoint individual sources; the merge accepts only exactly 200 unique ordered sources from all four committed shard definitions. Keep the unmodified per-source records and archive/kernel-log hashes.

Calculate whole-200-source bitrate and Top-1 curves before computing BD-rate Top-1, BD-accuracy and minimum same-QP Top-1 gap for `V6_vs_identity`, `V7_vs_identity`, and **direct `V7_vs_V6`**. Report every QP and the number of sources. Use the existing `src/metrics/bd_rate.py` and existing source-paired bootstrap logic unchanged: 2,000 percentile resamples with seed `20261004`, resampling the **source video** while keeping all QPs and three arms together. Report point estimates, 95% CI and valid resample counts. Do not average per-shard BD-rates.

The directional question is whether direct V7-versus-V6 `mc3_18` BD-rate is below zero; a 95% CI entirely below zero is stronger DEV evidence. A zero-crossing CI is inconclusive. A positive point estimate means no observed improvement. Even a favorable DEV result cannot establish independent transfer because these DEV sources and earlier `mc3_18` outcomes have been observed. Publish the result regardless of sign, with the two primary analyzers' already committed DEV results shown separately. Do not use this diagnostic to tune V7 or reuse the V6 holdout as a V7 confirmation.

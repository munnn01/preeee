# V9 H.265 chroma-only continuation: developmental CAL protocol

Status: fixed before implementing or running V9. This is a **development experiment**, not an independent holdout or an unseen-analyzer confirmation. Previous V2/V6/V7 and V8 outcomes, including `mc3_18`, have already been seen. The original research gate remains BD-rate Top-1 strictly below −15% on **both** primary analyzers at one codec; nothing here changes that gate. The user's additional engineering target is below −10% on both primaries while improving `mc3_18` relative to V6. No number is predicted in advance.

## Prior art and falsifiable rationale

[Wu et al., CVPR 2018](https://openaccess.thecvf.com/content_cvpr_2018/papers/Wu_Compressed_Video_Action_CVPR_2018_paper.pdf) and [Shou et al., CVPR 2019](https://openaccess.thecvf.com/content_CVPR_2019/papers/Shou_DMC-Net_Generating_Discriminative_Motion_Cues_for_Fast_Compressed_Video_Action_CVPR_2019_paper.pdf) show that motion/residual information matters for compressed-domain action recognition. V8's spatial motion-mask blur reduced Top-1 and failed on all analyzers; the [V8 result](RESULTS_V8_MOTION_CAL.md) is a motivating observation, not a source for V9 parameter fitting. [Lorkiewicz et al., IEEE Access 2025](https://multimedia.edu.pl/publications/Video-Coding-for-Machines-with-Neural-Network-based-Chroma-Synthesis.pdf) study removing/restoring chroma for machine vision and explicitly note that color can carry contextual information; their added decoder restoration is outside this project's pixel-before-standard-codec constraint. [Pourreza et al., ICCVW 2019](https://openaccess.thecvf.com/content_ICCVW_2019/papers/RLQ/Pourreza_Recognizing_Compressed_Videos_Challenges_and_Promises_ICCVW_2019_paper.pdf) focus an enhancement module on the luminance channel, but do not prove that chroma is irrelevant. V9 therefore tests a **mild** pre-codec chroma edit while keeping the original Y channel of the transformed stream byte-identical in YCrCb coordinates. Standard-compatible pre-codec preprocessing itself is established prior art in [Lu et al.](https://arxiv.org/abs/2206.05650) and [Zhao et al.](https://arxiv.org/abs/2512.15331). Novelty is not claimed from the color-space split alone.

H.265 only. Use exactly **positions 100–199** (zero-based) of the 200 IDs in the V2 CALIBRATION order in `configs/v7_dev_proxy_plan.json`, SHA-256 `5b0a32d1d0a1759b50232f0c297ee35ee5cfe0cfdf00c53b587781baa5afebc2`. No FIT, DEV, old TEST or holdout video or outcome is loaded for this experiment.

The comparator is the **existing frozen V6 H.265 policy**, models and V2 H.265 cache. Generate and commit a 100-source × five-QP V6 choice manifest from those pinned inputs **before Kaggle evaluation**, without reading `mc3_18` scores. The manifest fixes the identity and V6 stream name, measured cached bpp, source ID and source-video hash for each source/QP. Reject any mismatch with the original V2 cache, V6 frozen manifest or prior V7 CAL source hashes. The V6 policy is not retrained or changed.

The only new arm is `v6_chroma050`: generate V6's already selected six-candidate stream from the deterministic centered 16-frame, stride-2 128×128 source clip. For each RGB frame of that stream, use OpenCV `COLOR_RGB2YCrCb`; keep Y as the original uint8 Y channel; Gaussian-blur **Cr and Cb only** with `sigma=1.5`, then blend each chroma channel **50%** toward its blurred version, round to nearest uint8, and convert back with `COLOR_YCrCb2RGB`. There is one fixed strength, no grid, no spatial/motion mask, no per-video parameter, no decoder change or side information. Record mean absolute source-to-output Y difference after RGB roundtrip, so any unintended luminance change is visible rather than assumed away.

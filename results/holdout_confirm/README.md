# Frozen V2-C confirmatory holdout package

The preregistered 1,000 source-ID Kinetics-400 validation holdout was evaluated once with the frozen V2-C policy. H.264 and H.265 each used two 500-video Kaggle shards. The primary stage recorded all six candidates for `r2plus1d_18` and `r3d_18`; the independent `mc3_18` stage scored the identity and policy-selected streams. The two whole-video shards were merged **before** computing each codec's curves and 2,000 paired source-video bootstrap draws.

The original strict gate **fails** for both codecs. See the [holdout report](../../docs/RESULTS_HOLDOUT_CONFIRM.md) for BD-rate, confidence intervals, fixed-downscaling comparisons, and limitations. The result files are [H.264](h264_result.json) (SHA-256 `ab2183c1e3851abf0a704624fdfaf1de26d8b5199227b6559d747738b9c36f47`) and [H.265](h265_result.json) (SHA-256 `7b7125f3623ac0a38fc177dc6ff995cb340eb467d02dfe0feb5c6931bdb78f80`).

`raw/` contains the eight original stage manifest/record pairs; `notebooks/` contains the exact private Kaggle notebook sources and metadata; [run_provenance.json](run_provenance.json) binds their hashes to the result JSONs. [archive_manifest.json](archive_manifest.json) identifies the four original Kaggle output archives by SHA-256. [SHA256SUMS.txt](SHA256SUMS.txt) covers each committed file in this package, except itself. The input manifest is [input_manifest.json](input_manifest.json); actual video bytes remain in the private Kaggle datasets, with SHA-256 checks against the committed source list before model evaluation.
